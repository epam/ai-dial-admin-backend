## AI-DIAL Admin Backend (0.20.0)

This release adds a single configuration-management environment variable that makes the MSSQL Azure AD JDBC authentication mode configurable. The default preserves the previously hardcoded behavior, so no action is required for existing deployments. There are no changed defaults, deprecations, or removals.

---

## 1. New Environment Variables

| Setting | Default | Required (Yes/No) | Description |
| :--- | :--- | :--- | :--- |
| `MS_SQL_SERVER_AZURE_JDBC_AUTH_MODE` | `ActiveDirectoryMSI` | No | Azure JDBC authentication mode passed to the SQL Server driver (for example `ActiveDirectoryMSI`, `ActiveDirectoryDefault`). Applies only when `DATASOURCE_VENDOR=MS_SQL_SERVER` and `DATASOURCE_AUTH_TYPE=azure`. Must not be blank — the service fails to start on an empty value. |

Verified in code:

| Location | Detail |
| :--- | :--- |
| `src/main/resources/application.properties:144` | `sqlserver.datasource.azure-jdbc-auth-mode=${MS_SQL_SERVER_AZURE_JDBC_AUTH_MODE:ActiveDirectoryMSI}` |
| `MsSqlServerConfiguration#managedAzureAuthTypeDataSource` | Passes the value to the driver as the `authentication` data source property; throws `IllegalArgumentException` if blank. |

**Helm `values.yaml` — only if overriding the default:**

In the [dial-admin chart](https://github.com/epam/ai-dial-helm/tree/main/charts/dial-admin), `DATASOURCE_VENDOR` is rendered by the chart from `backend.configuration.datasourceVendor` (`mssql` → `MS_SQL_SERVER`) and must not be set under `backend.env`. The MSSQL branch also requires an external database (`postgresql.enabled: false` plus `externalDatabase.host`). Only `DATASOURCE_AUTH_TYPE` and the new variable go under `backend.env`.

```yaml
postgresql:
  enabled: false

externalDatabase:
  host: "my-sqlserver.database.windows.net"
  port: 1433
  database: dial_admin
  user: dial_admin

backend:
  configuration:
    # Renders DATASOURCE_VENDOR=MS_SQL_SERVER and the MS_SQL_SERVER_* connection env vars
    datasourceVendor: mssql
  env:
    DATASOURCE_AUTH_TYPE: azure
    # Omit to keep the default ActiveDirectoryMSI; never set to an empty string:
    MS_SQL_SERVER_AZURE_JDBC_AUTH_MODE: "ActiveDirectoryDefault"
    # Optional — sets the JDBC msiClientId property for user-assigned managed identity:
    AUTH_AZURE_CLIENT_ID: "<managed-identity-client-id>"
```

Postgres and H2 deployments are unaffected.
